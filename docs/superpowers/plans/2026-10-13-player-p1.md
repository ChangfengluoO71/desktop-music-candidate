# DMC Player P1 Implementation Plan

## Goal

Deliver the first offline-capable local music player milestone on the existing `main` branch: playback abstraction and engine, durable local queue, cover-wall/library controls, mini-player and now-playing view, local synchronized lyric tracks, and opt-in directory monitoring. Keep online account/session code outside the playback path.

## Architecture

`LocalMusicScreen` and the global mini-player observe one `PlayerViewModel`; commands flow through a serialized `PlaybackCoordinator` to `PlaybackEngine`. The local queue stores only local track IDs and paths. Artwork and lyric resolvers read local files. Directory notifications refresh the existing scanner/index through a bounded debounce path. Player lifecycle is closed before process shutdown.

## Tech Stack

Kotlin/JVM, Compose Desktop, coroutines/StateFlow, existing JNA and SQLite modules, Java NIO `WatchService`, and a replaceable playback-engine interface. The native playback backend is gated by an artifact/version/license/package smoke test before distribution. Deterministic tests use a fake engine and local fixtures.

## Spec

- Playback: play, pause, stop, previous/next, seek, volume, shuffle, repeat, queue add/remove/reorder/clear, end/error handling, and explicit queue restore without auto-playing on startup.
- Library: play from a track or album; artwork-backed album wall and searchable/filterable track list.
- Lyrics: load local embedded/sibling `.lrc`, `.tl.lrc`, and `.roma.lrc`; parse timestamps safely; switch original/translation/romanization; no online retrieval or audio-file writes.
- Monitoring: opt-in per registered root; debounce bursts; recover with a bounded rescan after overflow/restart/removable-drive reconnect; never delete source files.
- Lifecycle: release engine resources before exit; unavailable/unsupported codec errors remain actionable and do not crash the app.
- Packaging: pin and document any native runtime, its source, hash, license, and transitive DLLs; do not ship an unverified development binary.

## Global Constraints

- Work directly on `main`, preserving the existing docs edits and all existing tests.
- Keep playback completely offline and independent of NetEase Song ID, cookies, and session state.
- Do not modify Android or unrelated download/artwork behavior.
- Do not claim real-format or installed-player acceptance from fake-engine tests.
- Push the reviewed implementation and product documentation to the existing public GitHub repository after verification; do not create a release unless asked.

## Review Focus

- State serialization and cancellation around track changes, end events, and application shutdown.
- File path/metadata changes while tracks are queued or playing.
- Local-only privacy and zero network access in player workflows.
- Native dependency licensing and clean Windows Inno installer behavior.
- Existing installer identity and user data must remain compatible.
